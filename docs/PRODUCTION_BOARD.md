# Verification against the codebase

Checked on the working tree (branch `Development`). Each claim is tagged
**\[measured]** (a command + a number), **\[verified]** (read the file / ran it) or
**\[inferred]** (reasoned, flagged as such).

## How to read the status columns

|Status|Meaning|
|-|-|
|**Done**|Implemented and wired into the running game|
|**Partial**|Core exists, but the board's sub-items are only generically covered|
|**Stub**|Data/slot exists but nothing drives it|
|**Missing**|No code and no data anywhere in the repo|

## Systemic findings (these dominate the per-block results)

### 1\. Sound is effectively unimplemented — music only

`engine/audio.py` exposes exactly three functions: `play\_music`, `stop\_music`,
`set\_volume`. **There is no sound-effect API at all.** **\[verified]**
Only `game/main.py` and `game/ui/cutscene\_player.py` import it. **\[measured]**
`data/audio/` contains **1** file (`Bass\_and\_drum\_Duo.wav`). **\[measured]**

> Consequence: \*\*all 117 Sound cards\*\* on the board (Placement Sound, Attack Sound,
> Damage Sound, Death Sound, Repair Sound, Upgrade Sound, per-season music, …) are
> \*\*Missing\*\*, other than a single background music track and cutscene audio.
> This is the single largest gap between the board and the build.

### 2\. FX is real, but generic — not per-building

`game/ui/effects.py` implements a procedural VFX system driven by
`data/balancing/vfx.json`, which declares **10 procedural kinds**
(`announce, beam, crater, death\_burst, floaters, gold\_highlight, lightning, muzzle, projectile, slash`) and **10 triggers** (`building\_destroyed, building\_level\_up, building\_placed, building\_tier\_up, defender\_fire, enemy\_attack\_melee, enemy\_attack\_ranged, enemy\_death, projectile\_hit, splash\_impact`). **\[verified]**

> Consequence: the board's \~175 UI/FX cards are covered \*generically\*. A
> "Placement FX" exists for every building via the `building\_placed` trigger, but
> no building has bespoke FX. Marked \*\*Partial\*\* throughout.
> The `VFX` slot category has \*\*0 of 8\*\* slots bound to art. \*\*\[measured]\*\*

### 3\. Art is much earlier than slot-binding counts suggest

Counting *bound slots* overstates finished art badly, because a single still
frame imported into a slot renders fine and reads as done. Graded by what is
actually inside each sheet: **\[measured]**

|Category|Slots|Full set|Idle only|Static frame|Empty|
|-|-:|-:|-:|-:|-:|
|Buildings|92|18|26|48|0|
|Enemies|23|7|0|11|5|
|Map|19|0|16|0|3|
|UI|14|0|0|12|2|
|Deco|52|0|7|43|2|
|Tile Conditions|28|0|20|0|8|
|Core|5|0|0|1|4|
|VFX|8|0|0|0|8|
|Backgrounds|1|0|0|1|0|
|**Total**|**235**|**25**|**69**|**116**|**25**|

- **Full set** — every animation the category declares
- **Idle only** — animated, but idle is the only state
- **Static frame** — one still image standing in for the whole sheet

Only **25 slots (11%)** carry a complete animation set, and Defenders plus
Musicians account for nearly all of them. **116 slots are a single frame.**

Two further corrections to the earlier "87% bound" reading: the `kidnap`
animation is declared for enemies but **never imported**, and **Formation** has
no sprite slots in any era while **Boss era 4** has no slot. **\[measured]**

Per-feature art grades are in [`FEATURE_STATUS.md`](FEATURE_STATUS.md). All enemy
and boss art is slated for rework and all UI screens for reimport, so several
rows graded "present" below are nonetheless scheduled to be replaced.

### 4\. Seasons does not exist

The string `season` appears in **zero** `.py` and **zero** `.json` files in the
repo (excluding `balancing\_history/`). **\[measured]** There is no season state,
no season progression, no seasonal tiles, no seasonal music hook.

> The board carries a full Seasons block (Season Progression Logic, 4 seasonal
> background tile sprites, Season Change FX/UI/Sound, 8 seasonal music tracks)
> plus a Seasons roadmap card. \*\*All of it is Missing.\*\*

## Caveats

* Block-to-card ownership is derived geometrically (each card assigned to the
nearest purple User Story card above/left of it). Spot-checked and correct for
the blocks above, but a handful of edge cards near block boundaries could be
attributed to the wrong neighbour. **\[inferred]**
* "Done" means the system exists and is wired — not that it matches the board's
intended *design*. Behavioural parity was not tested.
* The board's per-tier art rows (Tier 2/3/4) were not individually checked
against the manifest beyond the category totals above.
